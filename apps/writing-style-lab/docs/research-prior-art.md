## 借进来的（已落地为代码）

1. **要具体，不要空泛**（perfectly-replicate「品味原则」第 3 条）：
   "平均句长 12 字，30% 的句子少于 8 字"有用，"喜欢用短句"没用。
   → 落地为 `src/shared/stylometry.ts`：本地先把句长分布、标点指纹、用字丰富度、人称占比算成数字，
   存进分析记录、显示在界面上，并且**拿这些数字去核对模型的说法**。

2. **指标要归一化、可复现**（StyloMetrix）：
   绝对次数会被文本长度带偏，所以标点、功能字、代词一律给「每 100 字」密度；全部指标无随机因素，
   同一输入永远同一输出（有测试断言）。

3. **中文不需要分词也能测**（text_para 的启发 + 我们的取舍）：
   用「字种数 / 字次」代替词汇丰富度，用「高频二字组合」给线索并**明确声明它不是词频**，
   避免引入分词依赖与词典不全的问题（text_para 自己也在 README 里承认词库不全）。

4. **跨篇重复才算真特征**（perfectly-replicate 第 1 条：出现 3+ 次才是风格，一次是即兴）：
   我们的工程门槛是「通用习惯至少 2 篇非重复样本」（沿用本任务书的规定，不改成 3），
   并且**把"非重复"真正做实**：同一文稿切出的片段算一份，近似重复（字二字组 Jaccard ≥ 0.85）
   也算一份 —— 否则复制粘贴就能凑出"两篇支持"。

5. **保留矛盾**（perfectly-replicate 第 2 条）：
   与我们已有的 `counterEvidence` / `limitations` 机制一致，导出时把反例数量与不一致说明写进规则卡。

6. **禁用清单比正向特征更能定义边界**（perfectly-replicate 第 4 条）：
   作者的「这段不代表我希望的风格」标记 → `origin: preference` 规则 → 进 SKILL.md 第 5 节
   「具体应避免的表达及例外」。

## 故意没有抄的

1. **「整体匹配度 >70% 为合格」**（perfectly-replicate Phase 4）：本任务书明确禁止未经验证的
   「还原度百分比」。我们只做 A/B 盲评 + 作者主观判断，不产出任何相似度分数。
2. **自动清洗语料**（去样板、去页眉页脚、余弦相似度去重后直接删）：与本任务书「不能更改原文」
   冲突。我们只**标记**近似重复，不删、不改用户丢进来的文字。
3. **依赖分词/词频库**：引第三方词典会带来「词库不全」的坑，且离线不可复现。
4. **直接安装成某平台的子技能**：本任务书要求「只有经过验证后才能声称能在某个具体平台自动加载」，
   所以我们只导出通用 Markdown Skill，不宣称平台集成。
