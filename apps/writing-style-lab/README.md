# 文风采样器（Writing Style Lab）

按写作框架亲自写样本，或**把已经写好的文字直接丢进来**；程序调用 DeepSeek 分析**作者本人样本**，
汇总可核查的文风规则；作者接受、修改或拒绝后，导出能给其他写作智能体用的 `SKILL.md`。

> Skill 是**结构化写作指令**，不是训练好的模型权重。本工具不承诺完美复制作者，
> 也不会给出“还原度百分比”这类未经验证的数字。

本应用是 [novel-writing-skill](../../README.md) 仓库里的一个本地工具，与 `.claude/skills/novel-*`
里的写作技能并存，互不影响：那些技能是“怎么写小说”的流程指令，这里是“把**你的**文风提炼成指令”。

## 它做什么 / 不做什么

**做**：写作任务卡 → 亲写或导入样本 → 来源标记与筛选 → 单篇分析 → 多篇归纳 → 原文依据核对 →
作者确认规则 → 导出 Skill → 换新题目做 A/B 对照试写。

**不做**（首版明确排除）：账号、支付、社区、自动发布、小说批量生成、联网采集、向量库、微调、
复杂智能体调度平台、公共 API 发布。

## 快速开始

```bash
cd apps/writing-style-lab
npm install
cp .env.example .env      # 填 DEEPSEEK_API_KEY；没有 Key 也能写作、备份、确认规则、预览导出
npm run dev               # 前端 http://127.0.0.1:5173（/api 走 Vite 代理）
```

生产构建（本地同源托管，只绑 127.0.0.1）：

```bash
npm run build             # 类型检查 + 构建到 dist/web
npm start                 # http://127.0.0.1:8787
```

配置项见 `.env.example`。要点：`DEEPSEEK_API_KEY` **只在服务端**（不要加 `VITE_` 前缀），
不进前端、不进浏览器存储、不进日志、不进备份、不进导出的 Skill。

## 使用流程

1. **选题目**：6 张内置任务卡（可改），默认每篇 300—600 字。题目主要限定人物、目标、事件和长度；
   你额外加的“全用短句”这类要求会存成框架约束，分析时必须识别它的影响。
2. **写样本 / 丢样本**：在编辑器里写，或走**直接采样**把旧文粘贴/导入进来。4—6 篇是使用建议，
   不是科学门槛；样本少也能分析，只是会显示为初步观察。可以把一篇标为**保留样本（holdout）**，
   本轮不发送，留给你事后人工对照规则。
3. **选样本**：只有「本人本次写作 / 本人旧文」且未被排除、非 holdout 的样本会进提炼清单；
   清单在分析前完整展示，并写明每篇为什么被排除。
4. **分析**：顺序执行、逐项保存、刷新可复用；每条观察都带原文引用，点开可回看高亮。
   引用不是原文的真实子串就**拒绝**，程序不会改写原文去迁就模型。
5. **确认规则**：接受 / 修改（要填理由，原说法保留）/ 拒绝，或手工加一条“本人指定偏好”。
   样本一改（正文版本、来源、是否入选、holdout），相关规则立刻重验并标记“需重新确认”。
6. **导出**：`SKILL.md`、`style-profile.json`，以及**可选**的 `references/evidence.md`（短摘录）。
   默认不含原稿、不含未确认/已拒绝规则、不含未经选择的摘录。
7. **对照试写**：换一个**未用于本轮提炼**的新题目，同一模型、同一参数生成两版，随机排成 A/B，
   **评价前隐藏条件**，你评价完再揭示。试写文本永远是 AI 生成，不会回流进你的样本库。

## 直接采样（把已经写好的文字丢进来）

- 入口与“从题目开始写作”**并列**，两步到分析：粘贴/导入 → 勾选是否入选 → 点分析。
- **原文不可更改**：程序不修改、不补写、不润色，也不做任何静默规范化——不转全角/半角、不改标点、
  不合并换行、不裁首尾空白、不删零宽字符与 BOM、不剥离 Markdown 标记。采样视图默认**只读**，
  要改就“另存为写作草稿”，原文版本不动。
- **来源自述要点一次**：我本人写的（本次写作）/ 我本人写的（旧文）/ 含 AI 生成 / 不确定。
  默认不预选；只有前两项才默认进提炼。
- **超限不静默截断**：单篇默认最多 6,000 字（含标点）。超限时给出“将切成 N 段，每段约 X 字”的预览，
  由你确认后切分；切分是**分区不是裁剪**，各片段拼接后与原文逐字一致。
  同一篇文稿切出的片段在归纳时**只算一份证据**，不会凑出“两篇支持”。
- **无题目 ⇒ 约束未知**：直接采样的样本没有题目约束，分析时约束影响一律记为“未知”，
  不会因为看不到要求就把短句之类特征说成你的通用习惯。可写一句写作背景（体裁、是否经过编辑润色）
  作为线索。

## 调用控制与费用

- 打字、保存、确认规则、预览、导出**都不调用模型**；只有你点“分析/重新归纳/试写”才发请求。
- 分析前展示待发送清单与本轮最大计划调用次数（新样本数 + 1 次归纳 + 2 次重试额度）。
- 上限：单篇 6,000 非空白字符、单批 10 篇、单批总量 30,000；前后端同时校验。
- 同一「正文版本 + 约束版本 + 模型 + 提示词版本」复用已成功结果；相同任务双击不重复发起（服务端 409 去重）。
- 超时保护；只对 429 / 临时服务错误重试，尊重 `Retry-After`，一个批次额外重试总量上限 2 次；
  401 等配置错误不重试。截断、空结果、JSON/证据错误都给出明确原因，不会循环重试到“碰巧成功”。
- 保存真实返回的 usage 与耗时；未提供费用信息时显示“未知”。

## 数据与隐私

- 稿件、样本、分析、规则、试写记录都存在**你自己的浏览器 IndexedDB** 里；服务端不落库。
- 服务端只记录必要的请求元信息（路由、状态、模型、token 数、耗时），**不记录正文**。
- 备份 JSON **包含完整正文**（可能含私人内容），与导出的 Skill 明确区分；
  导入会先校验、先预览冲突，需你选择 skip / overwrite / duplicate，不会静默覆盖。
- 导出的 Skill 默认不含原稿、不含密钥、不含请求日志。

```
├─ tests/        Vitest：按验收标准逐条对应

```

## 已知限制

- **真实 DeepSeek 调用尚未验证**：仓库里没有配置 API Key，接口按官方文档实现并做了参数与错误处理，
  但“真实返回能否通过校验”没有实测结论，见 `docs/acceptance.md`。
- 一次 A/B 不能证明 Skill 有效；换题目多轮对比才有参考价值。
- 归纳是**工程门槛**（通用规则至少两篇非重复样本），不是统计保证。
- 采样视图只读是刻意设计：要改字请另存为草稿，原文不会被就地修改。
- 已下载到别处的文件不受本应用控制——导出后请自行管理。

### Mock（只在没有 Key 时自检链路用）

Mock **默认关闭**，而且要两道开关同时打开才会生效：启动时设 `ALLOW_MOCK_ANALYSIS=1`，
并且请求体里显式带 `"mock": true`（界面不提供这个入口，用 curl 调接口时手动加）。
只开环境变量不带 `mock: true` 时仍走真实调用，避免“没配 Key 就偷偷变成 Mock”。
Mock 结果带 Mock 标记、usage 显示“未知”，并且**不能导出为正式作者 Skill**。

```bash
# 自检：分析 → 归纳 → 试写 全链路（不碰真实 API）
```
